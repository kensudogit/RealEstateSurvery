# ゴールデンセット

実際に届いたメール 20〜30 通を、正解データ付きでここに固定する。
これが無いと「プロンプトを直したら良くなった気がする」から先に進めない。

## 生成済みのサンプル

実物のマイソクが揃うまでの間、抽出の落とし穴を意図的に踏ませるサンプルを
用意してあります。作り直すときは次を実行してください。

```bash
python tools/make_sample_mysoku.py --out backend/tests/golden
```

| ケース | 内容 | 仕込んである落とし穴 |
|---|---|---|
| `case_001` | 白金台の区分マンション | 和暦「平成5年3月築」／坪の併記／9,800万円表記／全角「２ＬＤＫ＋Ｓ」／罫線を省略した表／FAX ヘッダ・手書きメモ・朱印 |
| `case_002` | 経堂の一棟アパート | 全角数字の面積／億と万の混在価格／年収と利回りの整合（検算が誤検知しないこと） |
| `case_003` | 情報の薄い案件 | 正解 21 項目のうち 16 項目が「値なしが正解」。**捏造を検出するための最重要ケース** |

実物が手に入ったら、これらは残したまま `case_101` 以降に追加していってください。
合成サンプルは落とし穴の回帰テストとして機能し続けます。

## 置き方

```text
case_001/
  meta.json          件名・差出人・受信日時
  body.txt           メール本文（無ければ省略可）
  attachments/       添付 PDF・画像
  expected.json      人が入力した正解
  _cached.json       抽出結果のキャッシュ（自動生成・gitignore 済み）
```

`expected.json` は envelope ではなく素の値だけでよい。確信度は評価対象ではなく、
値が合っているかだけを見る。

```json
{
  "property_name": "渋谷ハイツ",
  "price": 48000000,
  "exclusive_area_sqm": 62.5,
  "built_year_month": "1993-03",
  "floor_plan": "2LDK",
  "structure": null
}
```

## ケースを偏らせない

実務で来るものを網羅する。

- テキストだけのメール / PDF 添付 / 画像だけ（FAX スキャン）
- 売買 / 賃貸 / 収益一棟 / 土地
- 表がきれいなもの / 罫線が省略されたもの / 手書きメモ入り
- 和暦表記 / 坪表記 / 万円と円の混在
- **情報がほとんど無いスカスカの案件**

最後のケースを必ず入れる。情報が薄い資料でモデルが埋めにくるかどうかが、
このシステムの安全性を決める。

## 実行

```bash
pytest tests/test_golden_accuracy.py -s                    # キャッシュを使う
pytest tests/test_golden_accuracy.py -s --refresh-golden   # 実際に API を呼ぶ
```

`-s` を付けると項目別の精度サマリが出る。取得率より捏造率と見逃し率を優先する。
取れない項目は人が入れれば済むが、間違った値が黙って通ると営業事故になる。

## 個人情報の扱い

実メールをそのまま置く場合は、リポジトリの公開範囲を必ず確認すること。
社外秘の物件情報・個人名・連絡先が含まれる。公開リポジトリなら別管理にする。
